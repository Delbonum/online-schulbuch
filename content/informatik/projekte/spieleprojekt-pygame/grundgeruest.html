Fast jedes Spiel – vom Handyspiel bis zum großen Konsolentitel – ist innen gleich aufgebaut: Eine Schleife läuft viele Male pro Sekunde und das Spiel befindet sich immer in einem bestimmten Zustand (Startbildschirm, Spiel, Endbildschirm …). Wenn du diese beiden Ideen verstehst, findest du dich in jedem Spielcode zurecht – auch in Code, den eine KI geschrieben hat.

Typ: Kernseite der Vorbereitung, 2–3 Lektionen mit Übungen. Wer an der Schule einen eigenen PyGame-Kurs nutzt (z. B. einen Kurs in PyCharm), kann die Seite als Zusammenfassung danach einsetzen: Die Begriffe Spielschleife, Ereignis und Zustand sollten am Ende allen geläufig sein, denn die Änderungsaufträge bauen darauf auf. Die Aufwärmaufgaben in Abschnitt 4 sind zugleich eine erste Übung für das Format des Änderungsauftrags.

1. Die Spielschleife

Ein Spiel wartet nicht, bis du etwas tust. Es läuft ständig weiter – meist 60-mal pro Sekunde. Bei jedem Durchlauf passieren drei Dinge, immer in derselben Reihenfolge:

  • Ereignisse verarbeiten: PyGame sammelt alles, was seit dem letzten Durchlauf passiert ist – eine Taste wurde gedrückt, die Maus geklickt, das Fenster geschlossen. Dein Programm geht diese Liste durch und reagiert.
  • Aktualisieren: Figuren bewegen sich ein kleines Stück, das Programm prüft Zusammenstöße (Kollisionen), zählt Punkte, prüft, ob das Spiel vorbei ist.
  • Zeichnen: Das Fenster wird gelöscht und alles an der neuen Position neu gemalt. Weil das so schnell geht, sieht es aus wie eine flüssige Bewegung – wie beim Daumenkino.

2. Zustände

Dein Spiel zeigt nicht immer dasselbe: Zuerst kommt ein Startbildschirm, dann das eigentliche Spiel, am Ende ein Endbildschirm mit den Punkten. Jeden dieser Abschnitte nennt man einen Zustand. Das Programm merkt sich in einer Variablen, in welchem Zustand es gerade ist, und macht in der Spielschleife je nach Zustand etwas anderes. Ein Übergang wechselt von einem Zustand in einen anderen – zum Beispiel, wenn du auf „Start“ klickst.

Solche Diagramme heißen Zustandsdiagramme. Sie sind ein wichtiges Werkzeug der Informatik (mehr dazu im Kapitel „Formale Sprachen & Automaten“). Für dein eigenes Spiel zeichnest du in der Projektskizze ein solches Diagramm – mit allen Bildschirmen, die dein Spiel haben soll.

3. Das Grundgerüst im Code

Hier ist ein vollständiges, lauffähiges Grundgerüst mit drei Zuständen. Das „Spiel“ ist noch ein Platzhalter: Du schiebst ein Quadrat mit den Pfeiltasten hin und her, nach zehn Sekunden ist es vorbei. Kopiere den Code in eine Datei main.py und starte ihn.

import pygame

BREITE, HOEHE = 800, 600

pygame.init()
fenster = pygame.display.set_mode((BREITE, HOEHE))
pygame.display.set_caption("Mein Spiel")
uhr = pygame.time.Clock()
schrift = pygame.font.Font(None, 48)

zustand = "start"   # "start", "spiel" oder "ende"
punkte = 0
spieler = pygame.Rect(380, 500, 40, 40)


def zeichne_text(text, y):
    bild = schrift.render(text, True, (255, 255, 255))
    fenster.blit(bild, bild.get_rect(center=(BREITE // 2, y)))


laeuft = True
while laeuft:
    # 1. Ereignisse verarbeiten
    for ereignis in pygame.event.get():
        if ereignis.type == pygame.QUIT:
            laeuft = False
        elif ereignis.type == pygame.KEYDOWN:
            if ereignis.key == pygame.K_ESCAPE:
                laeuft = False
            elif zustand == "start" and ereignis.key == pygame.K_RETURN:
                zustand = "spiel"
                punkte = 0
            elif zustand == "ende" and ereignis.key == pygame.K_RETURN:
                zustand = "start"

    # 2. Aktualisieren
    if zustand == "spiel":
        tasten = pygame.key.get_pressed()
        if tasten[pygame.K_LEFT]:
            spieler.x -= 5
        if tasten[pygame.K_RIGHT]:
            spieler.x += 5
        punkte += 1
        if punkte >= 600:   # Platzhalter: nach 10 Sekunden ist Schluss
            zustand = "ende"

    # 3. Zeichnen
    fenster.fill((20, 30, 50))
    if zustand == "start":
        zeichne_text("Mein Spiel", 250)
        zeichne_text("Enter: Start   Esc: Beenden", 350)
    elif zustand == "spiel":
        pygame.draw.rect(fenster, (240, 200, 60), spieler)
        zeichne_text(f"Punkte: {punkte}", 40)
    elif zustand == "ende":
        zeichne_text(f"Ende! Punkte: {punkte}", 250)
        zeichne_text("Enter: zurück zum Start", 350)
    pygame.display.flip()
    uhr.tick(60)

pygame.quit()

In eurem Projekt wird der Code viel länger. Dann lohnt es sich, ihn auf mehrere Dateien aufzuteilen – zum Beispiel eine Datei pro Bildschirm (startscreen.py, gamescreen.py …) und eine für Buttons. Vielleicht kennst du so eine Aufteilung schon aus einem PyGame-Kurs. Das Prinzip bleibt dasselbe: eine Spielschleife, ein Zustand, Ereignisse – Aktualisieren – Zeichnen.

4. Teste dein Verständnis

Was passiert, wenn du die Zeile uhr.tick(60) löschst?

  • Das Spiel friert ein.
  • Das Spiel läuft so schnell, wie der Computer kann – das Quadrat rast, und die zehn Sekunden sind viel schneller vorbei.
  • Nichts, die Zeile ist nur ein Kommentar.

Mit der Leertaste soll die Figur einmal springen, auch wenn man die Taste gedrückt hält. Wo gehört die Abfrage hin?

  • In die Ereignisschleife, als KEYDOWN-Ereignis.
  • Zu pygame.key.get_pressed() unter „Aktualisieren“.
  • Unter „Zeichnen“.

Warum steht beim Wechsel von "start" zu "spiel" die Zeile punkte = 0?

  • Damit Python die Variable kennt.
  • Damit jede neue Runde wieder bei null beginnt.
  • Damit der Highscore gespeichert wird.

Was siehst du, wenn du fenster.fill((20, 30, 50)) löschst?

  • Ein schwarzes Fenster.
  • Das Quadrat hinterlässt beim Bewegen eine Spur, und die Texte überlagern sich.
  • Eine Fehlermeldung.

5. Aufwärmen: kleine Änderungen

Diese Aufgaben sind genau von der Art, wie sie später im Änderungsauftrag vorkommen. Löse sie ohne KI und notiere zu jeder Aufgabe in einem Satz, wo du etwas geändert hast und warum dort.

Aufgabe 1: Das Quadrat soll sich auch nach oben und unten bewegen lassen.

Aufgabe 2: Das Quadrat darf das Fenster nicht verlassen. Tipp: Ein Rect kennt left, right, top und bottom.

Aufgabe 3: Auf dem Endbildschirm soll zusätzlich stehen: „Q: Beenden“. Die Taste Q beendet dort das Programm.

Aufgabe 4: Das Spiel soll nicht nach zehn, sondern nach zwanzig Sekunden enden. Wo genau musst du etwas ändern – und was passiert mit den Punkten?

  • Aufgabe 1: Unter „Aktualisieren“ zwei weitere Abfragen ergänzen: if tasten[pygame.K_UP]: spieler.y -= 5 und if tasten[pygame.K_DOWN]: spieler.y += 5. Dort, weil die Bewegung bei gedrückter Taste gleichmäßig in jedem Durchlauf geschehen soll.
  • Aufgabe 2: Nach den Bewegungen, noch im Zustand „spiel“: spieler.clamp_ip(fenster.get_rect()) oder einzeln, z. B. if spieler.left < 0: spieler.left = 0 und if spieler.right > BREITE: spieler.right = BREITE (entsprechend oben/unten). Wichtig ist die Stelle nach der Bewegung, sonst ist das Quadrat für ein Bild außerhalb.
  • Aufgabe 3: Unter „Zeichnen“ im Zustand „ende“ eine dritte Zeile zeichne_text("Q: Beenden", 420); in der Ereignisschleife elif zustand == "ende" and ereignis.key == pygame.K_q: laeuft = False. Einmaliges Ereignis, darum bei KEYDOWN.
  • Aufgabe 4: 600 durch 1200 ersetzen. Die Punkte zählen die Bilder (60 pro Sekunde), sie werden also doppelt so hoch. Gute Antworten erkennen, dass Punkte und Zeit hier dieselbe Variable sind – und schlagen evtl. eine eigene Variable für die Zeit vor (Übergang zur Frage, was ein sinnvoller Punktestand ist).
