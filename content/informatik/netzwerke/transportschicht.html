1. Wozu eine Transportschicht?

Bisher haben wir so getan, als passe jede Nachricht in ein einziges Paket und komme garantiert an. In Wirklichkeit gibt es drei Probleme:

  • Größe: Ein Paket darf höchstens etwa 1,5 Kilobyte groß sein. Ein Foto oder eine Webseite muss also in Hunderte Pakete zerlegt werden – und beim Empfänger wieder richtig zusammengesetzt.
  • Zuverlässigkeit: Unterwegs können Pakete verloren gehen, doppelt ankommen oder sich überholen, weil sie verschiedene Wege nehmen.
  • Zuordnung: Auf einem Rechner laufen viele Programme gleichzeitig, die alle Daten empfangen: Browser, Messenger, Musik-App. Wem gehört welches Paket?

Um all das kümmert sich die Transportschicht – zwischen Anwendung und Vermittlung. Ihre wichtigsten Protokolle heißen TCP und UDP.

2. Paket-Puzzle

  1. Gruppenaktivität: Eure Gruppe bekommt einen kurzen Text. Zerschneidet ihn in Schnipsel mit je etwa fünf Wörtern. Jeder Schnipsel ist ein Paket. Schickt die Pakete einzeln über verschiedene Boten an eine andere Gruppe; die Lehrkraft fängt dabei heimlich ein Paket ab und hält eines eine Weile zurück. Die Empfänger sollen den Text wiederherstellen.
  2. Was ist schiefgegangen? Welche Angaben hätten auf jedes Paket gehört, und welche Regeln hätten Sender und Empfänger vereinbaren müssen?

Typische Ergebnisse: Reihenfolge unklar → Nummern auf die Pakete (Sequenznummern); Verlust unbemerkt → Empfänger bestätigt erhaltene Pakete, Sender schickt nach einer Wartezeit erneut; Ende unklar → Gesamtzahl oder „letztes Paket“ markieren; zu Beginn klären, ob der Empfänger bereit ist → Verbindungsaufbau. Das ist genau TCP.

3. Ports: Wohnungsnummern für Programme

Die IP-Adresse führt ein Paket zum richtigen Rechner – wie eine Hausanschrift zum richtigen Haus. Damit es beim richtigen Programm landet, braucht es zusätzlich eine Portnummer – wie die Wohnungsnummer im Haus. Serverprogramme warten an festen, allgemein bekannten Ports:

PortDienst
53DNS (Namensauflösung)
80HTTP (Webseiten)
443HTTPS (verschlüsselte Webseiten)
25 / 587SMTP (E-Mail versenden)
993IMAP (E-Mail abrufen, verschlüsselt)

Der Client bekommt für jede Verbindung vom Betriebssystem einen zufälligen, freien Port (meist über 49152). So kann der Browser gleichzeitig mehrere Verbindungen offen haben, ohne dass die Antworten durcheinandergeraten.

4. TCP: verbindungsorientiert und zuverlässig

TCP (Transmission Control Protocol) baut zuerst eine Verbindung auf, nummeriert alle Daten, lässt sich jeden Empfang bestätigen und schickt verlorene Pakete erneut. Der Verbindungsaufbau heißt Three-Way-Handshake („Drei-Wege-Handschlag“):

UDP (User Datagram Protocol) ist das Gegenstück: kein Verbindungsaufbau, keine Bestätigungen, keine Wiederholung. Dafür ist es schnell und schlank. UDP eignet sich, wenn eine kurze Frage-Antwort genügt (DNS) oder wenn ein verlorenes Paket weniger schlimm ist als eine Verzögerung (Videotelefonie, Online-Spiele).

Im Schichtenmodell bekommt die Nachricht damit einen weiteren Umschlag: Die Anwendungsdaten stecken in einem TCP-Segment (mit Ports und Nummern), das im IP-Paket steckt, das im Ethernet-Rahmen steckt.

  2. Warum braucht es bei TCP drei Nachrichten für den Verbindungsaufbau – würden zwei nicht reichen?

Aufgabe 3 prüft sich selbst. Aufgabe 4: Beide Seiten wollen sicher sein, dass ihre Nachrichten beim anderen ankommen. Nach SYN und SYN-ACK weiß der Client, dass der Server ihn hört und antwortet; der Server weiß aber noch nicht, ob seine Antwort angekommen ist – das bestätigt erst das dritte ACK. Dabei werden auch die Startnummern beider Seiten ausgetauscht.

5. Experimente

  1. Öffne ein paar Webseiten und gib dann in der Konsole ein: netstat -n (Windows und Mac). Jede Zeile ist eine Verbindung. Welche Ports benutzt dein Rechner, welche die Gegenseite? Welche Gegenseiten-Ports kommen besonders oft vor?
  2. In der Netzwerk-Simulation: Installiere auf einem Rechner den Echo-Server (starten nicht vergessen) und auf einem anderen den einfachen Client. Verbinde dich mit dem Echo-Server (Port 55555), schicke zwei Nachrichten und trenne die Verbindung. Finde im Datenaustausch den Three-Way-Handshake, die Daten mit Bestätigungen und den Verbindungsabbau. Gib während der Verbindung auf dem Server netstat ein.
So sieht die Ausgabe von netstat -n ungefähr aus 
Aktive Verbindungen

  Proto  Lokale Adresse         Remoteadresse          Status
  TCP    192.168.178.34:52114   94.130.236.154:443     HERGESTELLT
  TCP    192.168.178.34:52120   185.15.59.224:443      HERGESTELLT
  TCP    192.168.178.34:52131   142.250.185.67:443     WARTEND

Hinter dem Doppelpunkt steht der Port. Lokal: zufällige hohe Ports des Clients; Gegenseite: meist 443 (HTTPS). „HERGESTELLT“ heißt: Der Handshake ist abgeschlossen; „WARTEND“: Die Verbindung wird gerade abgebaut.

Aufgabe 5: Gegenseite fast immer Port 443 (HTTPS), seltener 80; lokale Ports zufällig und hoch, für jede Verbindung ein anderer. Aufgabe 6: Im Datenaustausch: SYN, SYN-ACK, ACK; dann je Nachricht ein Datensegment (PSH, ACK) mit Bestätigung und die Antwort des Servers; zum Schluss FIN, ACK in beide Richtungen und ein letztes ACK. netstat zeigt die offene Verbindung mit beiden Ports.
