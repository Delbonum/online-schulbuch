1. Namen statt Nummern

Im Netz werden Pakete an IP-Adressen geschickt. Aber wer merkt sich schon 185.15.59.224? Viel leichter ist ein Name wie wikipedia.org. Damit dein Rechner trotzdem weiß, wohin er die Pakete schicken muss, gibt es das DNS (Domain Name System). Es funktioniert wie ein riesiges Telefonbuch: Zu jedem Namen findet man dort die zugehörige IP-Adresse.

Gibst du einen Namen ein, fragt dein Rechner zuerst einen DNS-Server: „Welche IP-Adresse gehört zu wikipedia.org?“ Welchen DNS-Server er fragt, steht in seinen Netzwerkeinstellungen (du hast ihn bei ipconfig /all gesehen). Der DNS-Server antwortet mit der IP-Adresse – und erst dann schickt dein Rechner die eigentliche Anfrage los. Die Namensauflösung ist ein eigenes, kleines „Gespräch“ auf der Anwendungsschicht.

Kein einzelner DNS-Server kennt alle Namen der Welt. Kennt er einen Namen nicht, fragt er bei anderen DNS-Servern nach – von den Root-Servern über die Server für die Endung (z. B. .de) bis zu dem Server, der für die Domain zuständig ist. Antworten werden eine Weile zwischengespeichert (DNS-Cache), auch auf deinem eigenen Rechner. So geht es beim nächsten Mal schneller.

2. Domain und URL

Der Name eines Rechners im Internet heißt Domain (genauer: Domainname). Die vollständige Adresse eines einzelnen Dokuments – einer Webseite, eines Bildes, einer Datei – heißt URL (Uniform Resource Locator). Die Domain ist also nur ein Teil der URL:

https://online-schulbuch.de/informatik/netzwerke/dns/
└─┬──┘  └───────┬─────────┘└───────────┬──────────┘
Protokoll     Domain             Pfad zur Ressource
└──────────────────── URL ────────────────────────┘

Die Domain endet mit der Top-Level-Domain (TLD), z. B. .de für Deutschland, .ch für die Schweiz oder .org für Organisationen. Davor können weitere Teile stehen, sogenannte Subdomains wie www. oder de. in de.wikipedia.org. Der DNS-Server übersetzt nur die Domain in eine IP-Adresse – den Pfad wertet erst der Server am Ziel aus.

  1. Markiere in der URL https://www.beispiel.ch/ordner/datei.html: Protokoll, Domain, Top-Level-Domain und Pfad.
  2. Viele URLs teilen sich dieselbe Domain – und manchmal teilen sich sogar viele Domains dieselbe IP-Adresse. Wie kann das sein?

Aufgabe 1: Protokoll https, Domain www.beispiel.ch (mit Subdomain www), TLD .ch, Pfad /ordner/datei.html.

Aufgabe 2: Alle Seiten einer Website liegen auf demselben Server (gleiche Domain, verschiedene Pfade). Und ein Server kann viele Websites ausliefern (Webhosting): Der Browser schickt den gewünschten Domainnamen in seiner HTTP-Anfrage mit, damit der Server weiß, welche Website gemeint ist.

3. Experiment: DNS in der Konsole

  1. Frage den DNS-Server nach der IP-Adresse einer Domain: 
    nslookup online-schulbuch.de
nslookup wikipedia.org
    Welcher DNS-Server antwortet? Welche IP-Adressen bekommst du?
  2. Schau dir an, welche Namen dein Rechner schon zwischengespeichert hat, und leere dann den Speicher (Windows): 
    ipconfig /displaydns
ipconfig /flushdns
ipconfig /displaydns
    Rufe danach eine Webseite im Browser auf und schau noch einmal nach. Was beobachtest du?
  3. Gib die IP-Adresse, die du für wikipedia.org bekommen hast, direkt in die Adresszeile des Browsers ein. Was passiert?
So sieht die Ausgabe von nslookup ungefähr aus – mit Erklärung 
C:\> nslookup wikipedia.org
Server:  fritz.box
Address:  192.168.178.1

Nicht autorisierende Antwort:
Name:    wikipedia.org
Addresses:  2a02:ec80:300:ed1a::1
          185.15.59.224
  • Server / Address: der DNS-Server, den dein Rechner gefragt hat – zu Hause oft der Router, der die Frage seinerseits an den DNS-Server des Providers weiterreicht.
  • Nicht autorisierende Antwort: Der befragte Server ist nicht selbst für die Domain zuständig; er hat die Antwort von einem anderen Server oder aus seinem Cache.
  • Addresses: die IP-Adressen der Domain, hier eine IPv6- und eine IPv4-Adresse. Große Websites haben oft mehrere.

ipconfig /displaydns zeigt den DNS-Cache des Rechners (Name, Typ des Eintrags, „Gültigkeitsdauer“ in Sekunden, IP-Adresse), ipconfig /flushdns leert ihn. Auf dem Mac geht das Leeren mit sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder.

  • Aufgabe 3: Antwortender Server ist der DNS-Server aus ipconfig /all (Schulserver oder Router). Große Seiten liefern mehrere Adressen, oft IPv4 und IPv6.
  • Aufgabe 4: Nach /flushdns ist der Cache (fast) leer; nach dem Aufruf einer Webseite stehen dort wieder Einträge – nicht nur für die Seite selbst, sondern auch für eingebundene Dienste (Bilder, Schriften, Werbung, Statistik). Das macht sichtbar, wie viele Server beim Aufruf einer Seite beteiligt sind. Für /flushdns sind meist keine Administratorrechte nötig, sonst Aufgabe gemeinsam am Lehrerrechner.
  • Aufgabe 5: Teils erscheint die Seite, teils eine Fehlermeldung oder eine Zertifikatswarnung: Viele Server liefern ohne Domainnamen nicht die gewünschte Website aus (siehe Aufgabe 2). Das zeigt, dass DNS bequem, aber für die Paketzustellung selbst nicht nötig ist.

  4. Probiere auch den Befehl host anna.lan in der Befehlszeile der Simulation. Was passiert, wenn du einen Namen abfragst, der nicht in der Tabelle steht?

Aufgabe 8: Zuerst geht eine DNS-Anfrage vom Absender an den DNS-Server (beim allerersten Mal davor ARP nach der MAC des DNS-Servers), der DNS-Server antwortet mit der IP-Adresse. Erst dann folgt der eigentliche Datenaustausch direkt zwischen Absender und Ziel (ggf. mit ARP nach der MAC des Ziels), ohne Beteiligung des DNS-Servers. Aufgabe 9: Für unbekannte Namen meldet die Befehlszeile, dass der Name nicht aufgelöst werden kann; dasselbe passiert, wenn der DNS-Server nicht gestartet ist.

Was macht ein DNS-Server?

  • Er übersetzt IP-Adressen in MAC-Adressen.
  • Er übersetzt Domainnamen in IP-Adressen.
  • Er leitet Pakete zwischen Netzen weiter.

Was ist der Unterschied zwischen Domain und URL?

  • Es gibt keinen.
  • Die Domain ist der Name des Servers, die URL die vollständige Adresse eines Dokuments.
  • Die URL ist ein Teil der Domain.

Welche Zuordnung ist richtig?

  • ARP: Name → IP; DNS: IP → MAC
  • DNS: Name → IP; ARP: IP → MAC
  • DNS und ARP machen dasselbe.

Der DNS-Server deiner Schule fällt aus. Was passiert?

  • Gar nichts geht mehr, auch nicht mit IP-Adressen.
  • Webseiten lassen sich über ihren Namen nicht mehr aufrufen, über die IP-Adresse aber schon.
  • Nur Webseiten mit .de funktionieren nicht mehr.

Frage 3 prüft eine häufige Verwechslung und eignet sich als Diagnose vor Rollenspiel II.
