1. Die Adresse einer Webseite: die URL

Eine URL (Uniform Resource Locator) ist die genaue „Adresse“ einer Ressource im World Wide Web – einer Webseite, eines Bildes oder einer Datei. Sie besteht aus mehreren Teilen:

https://www.beispiel.ch/dokumente/reglemente.html
└─┬─┘   └┬┘ └──┬───┘└┬┘ └───┬────┘ └──────┬──────┘
Protokoll│  Domain  TLD   Ordner       Dateiname
       Subdomain
  • Protokoll (https): wie die Daten übertragen werden; heute fast immer HTTPS, die verschlüsselte Form von HTTP.
  • Domain (www.beispiel.ch): der Name des Servers, den DNS in eine IP-Adresse übersetzt.
  • Pfad (/dokumente/reglemente.html): wo die Datei auf diesem Server liegt – wie ein Ordnerpfad auf deinem Rechner.

Eine URL ist für das Web, was die Postanschrift für die echte Welt ist: Sie sagt dem Browser genau, wo etwas zu finden ist.

2. Wer ist beteiligt?

Browser
ein Programm, mit dem man Dateien aus dem WWW anfordert, indem man eine URL angibt, und das die empfangenen Dateien (vor allem HTML) als Webseite darstellt. Der Browser ist ein Client. Das eigentliche Senden und Empfangen übernimmt das Betriebssystem.
Webserver
ein Programm, das ständig auf Anfragen wartet und die gewünschten Dateien ausliefert – ein Server.
Host
der Rechner, auf dem der Webserver läuft – bzw. die Firma, die solche Rechner und Speicherplatz für Webseiten, E-Mail oder Datenbanken bereitstellt (Webhosting). Wer eine Website betreibt, mietet meist Speicherplatz bei einem Host.
Provider
der Internetanbieter, der dir den Zugang zum Internet bereitstellt (Leitung, öffentliche IP-Adresse, oft auch den Router und einen DNS-Server) – gegen eine Gebühr.
Backbone
die großen Netze von Routern auf regionaler bis globaler Ebene, die die Pakete zwischen den Providern weiterleiten.

3. Ein Seitenaufruf Schritt für Schritt

  1. Du gibst eine URL in den Browser ein, z. B. https://online-schulbuch.de.
  2. Der Browser erstellt eine HTTP-Anfrage (englisch HTTP-Request) und übergibt sie dem Betriebssystem: 
    GET /index.html HTTP/1.1
Host: online-schulbuch.de
  3. Das Betriebssystem kennt die IP-Adresse zu online-schulbuch.de noch nicht und stellt eine DNS-Anfrage an seinen DNS-Server. Der antwortet mit der IP-Adresse.
  4. Jetzt geht die HTTP-Anfrage auf die Reise: Die Ziel-IP liegt nicht im eigenen Netz, also an das Gateway (nach einer ARP-Anfrage nach dessen MAC). Von dort leiten Router die Pakete durch das Internet bis zum Webserver.
  5. Der Webserver empfängt die Anfrage und schickt die gewünschte HTML-Datei zurück – meist in vielen Paketen, denn ein Paket fasst nur etwa 1,5 Kilobyte. Das Betriebssystem des Clients sammelt die Pakete ein, setzt sie in der richtigen Reihenfolge zusammen und übergibt die Datei dem Browser.
  6. Der Browser beginnt mit der Darstellung – und merkt schnell, dass er noch mehr braucht: Stylesheets für das Aussehen, Bilder, Schriften, Skripte. Für jede dieser Dateien schickt er eine weitere HTTP-Anfrage. All das geschieht in wenigen Hundertstelsekunden.

Zwischen Schritt 3 und 4 baut das Betriebssystem eigentlich noch eine TCP-Verbindung zum Webserver auf („Hallo, bist du bereit?“ – „Ja!“ – „Gut, los geht’s.“). TCP sorgt auch dafür, dass alle Pakete vollständig und in der richtigen Reihenfolge ankommen. Mehr dazu auf der Seite Vertiefung: Die Transportschicht.

  1. Bringe die Schritte eines Seitenaufrufs in die richtige Reihenfolge.
    1. Die Nutzerin tippt eine URL in die Adresszeile.
    2. Der Browser erstellt eine HTTP-Anfrage.
    3. Das Betriebssystem fragt den DNS-Server nach der IP-Adresse der Domain.
    4. Das Betriebssystem fragt per ARP nach der MAC-Adresse des Gateways.
    5. Router leiten die HTTP-Anfrage durch das Internet zum Webserver.
    6. Der Webserver schickt die HTML-Datei in mehreren Paketen zurück.
    7. Der Browser stellt die Seite dar und fordert Bilder und Stylesheets an.
  2. Setze die passenden Begriffe ein: Client, Domain, Host, Provider, Router, Server, URL, User.

    Hans (1) öffnet einen Browser (2) und gibt in die Adresszeile www.nksa.ch/termine.html (3) ein. Der Browser fragt sein Betriebssystem nach der Datei. Da es sie noch nicht hat, sucht es im Internet danach. Dazu muss es unter anderem herausfinden, welche IP-Adresse zu www.nksa.ch (4) gehört. Zu dieser IP-Adresse gibt es einen Computer (5), auf dem das Programm (6) läuft, das die gewünschte Datei liefert. Voraussetzung für das alles ist ein Internetzugang, den Hans von einer Firma (7) gegen eine Gebühr bekommt. Von dieser Firma erhielt er ein kleines Gerät (8), das sein Heimnetz mit dem Internet verbindet.

4. Experiment: dem Browser über die Schulter schauen

  1. Öffne eine Webseite, klicke mit der rechten Maustaste auf einen Text und wähle Untersuchen (oder drücke F12). Suche im Bereich Elemente die Stelle im HTML, die zu diesem Text gehört, und ändere den Text per Doppelklick. Lade die Seite danach neu. Was passiert – und warum?
  2. Wechsle in den Entwicklerwerkzeugen zum Reiter Netzwerk und lade die Seite neu. Wie viele Anfragen schickt der Browser für eine einzige Seite? Von wie vielen verschiedenen Domains lädt er Dateien?

Aufgabe 3: Die Änderung ist sofort sichtbar, aber nur lokal: Der Browser zeigt seine eigene Kopie der Dateien an. Beim Neuladen holt er die Dateien erneut vom Server, und die Änderung ist weg. (Wichtig auch für Medienkompetenz: Screenshots von Webseiten lassen sich so leicht fälschen.) Aufgabe 4: Je nach Seite einige Dutzend bis mehrere hundert Anfragen, oft von vielen Domains (Schriften, Werbung, Statistik). Die Seiten dieses Schulbuchs kommen mit wenigen Anfragen von einer Domain aus.

5. Ein Seitenaufruf in der Simulation

  1. Öffne das Beispiel Kleines Internet mit DNS, DHCP und Webserver und starte die Simulation. Öffne auf „Schüler 1“ den Webbrowser und rufe www.schulbuch.test auf.
  2. Öffne den Datenaustausch von „Schüler 1“. Ordne die Einträge den sechs Schritten aus Abschnitt 3 zu. Welche Protokolle findest du, und zu welcher Schicht gehören sie?
  3. Ändere auf dem Webserver mit dem Text-Editor die Datei /webserver/index.html und rufe die Seite erneut auf.

Im Datenaustausch erscheinen (je nach Zeitpunkt): DHCP (Adresse beziehen – passiert beim Start), ARP nach dem Gateway, DNS-Anfrage an 10.0.0.53 und Antwort (Anwendung, über UDP), TCP-Verbindungsaufbau mit dem Webserver (Transport), HTTP-GET und HTTP-Antwort (Anwendung), TCP-Bestätigungen und Verbindungsabbau. Jede Nachricht hat Zeilen für Netzzugang (MAC) und Vermittlung (IP). Aufgabe 7 zeigt die Rolle des Hosts: Wer Zugriff auf den Server hat, bestimmt den Inhalt.

Was ist ein Browser?

  • ein Server, der Webseiten speichert
  • ein Client-Programm, das Dateien aus dem WWW anfordert und darstellt
  • ein anderer Name für das Internet

Was passiert, bevor die HTTP-Anfrage verschickt werden kann?

  • Der Webserver schickt die Seite.
  • Die Domain wird per DNS in eine IP-Adresse übersetzt.
  • Der Browser zeigt die Seite an.

Was ist der Unterschied zwischen Host und Provider?

  • Der Host stellt Speicherplatz für Webseiten bereit, der Provider den Internetzugang.
  • Es gibt keinen.
  • Der Provider speichert Webseiten, der Host verkauft Router.

Warum schickt der Browser für eine einzige Seite oft viele Anfragen?

  • Weil der Server beim ersten Mal nicht antwortet.
  • Weil die Seite weitere Dateien wie Bilder und Stylesheets einbindet.
  • Weil jede Anfrage nur einen Buchstaben überträgt.
